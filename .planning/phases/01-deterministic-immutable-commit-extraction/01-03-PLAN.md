  <name>Task 1: Select and parse manifests as bounded immutable evidence</name>
  <files>integrations/vibery-station/lib/node-workspace-evidence.mjs, integrations/vibery-station/test/node-workspace-evidence.test.mjs</files>
  <action>
Consume the reader's complete sorted tree inventory. Locate root `package.json` and resolve only the supported workspace forms/patterns against regular tree blobs; do not use filesystem globbing. Define segment wildcard matching over POSIX Git paths, require workspace roots to be unambiguous and disjoint, and reject dot/parent/empty segments. Exact patterns and one terminal `*` segment are supported; every other glob syntax is an explicit fallback reason.

For each selected regular manifest, call the reader's exact-OID `statBlob` before content access. A trustworthy size above 1 MiB, an aggregate selected size above 8 MiB, or more than 512 discovered `package.json` paths is an explicit sorted `station-fallback/*` policy reason and suppresses every content read/detail claim for the selected set. Otherwise read each blob by OID using its probed exact size. Detect NUL/binary content and fatal UTF-8; parse JSON with Node semantics and require the minimal field types used by the profile. A sound tree plus missing, non-regular, policy-oversized, binary, invalid-UTF-8, malformed-JSON, colliding, zero-match, or otherwise unsupported selected manifest produces sorted fallback reasons and suppresses all detailed-package eligibility. It must not emit whichever packages happened to parse as a partial detailed result. Missing/unavailable objects, malformed size probes, size/read disagreement, and other tree/object integrity failures from the reader remain hard failures and are never converted to reasons.
  </action>

It separately proves policy-size excess becomes whole-project fallback while unavailable objects or probe/read mismatches remain hard failures.</verify>
